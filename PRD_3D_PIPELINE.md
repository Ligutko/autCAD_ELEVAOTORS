## 1. Навіщо цей документ

Кінцевий результат тунелю — один зерновий комплекс у реальному масштабі, у який заходить камера. Всередині видно справжні вузли. На тій самій моделі показано один дефект, узятий з документа, а не вигаданий. Ролик 40–70 секунд має витримати людину, яка вміє 3D, і людину, яка тримає зерно.

Цей PRD описує систему, яка до цього результату доходить агентами. Перший агент, який бере документ, будує лише шар даних: що відомо, звідки це відомо, чого бракує. Збирач 3D читає тільки затверджені факти. Немає картки — деталь не будується.

Якісна планка: спеціаліст не соромиться моделі. Грошових обіцянок, термінів «місяць до чека» і фраз «геніально» у роботі немає.

## 4. Архітектура тунелю

Три шари, які не змішуються.

**Кіт.** Іменована деталь з розмірами: `silo_msvu_220`, `noria_n100_head`, `aeration_fan`. Новий тип деталі посеред збірки не створюється. Немає в кіті — задача падає з назвою відсутнього вузла.

**Світ.** Екземпляри кіта, розставлені за `SITE.json`.

**Розбір.** Який вузол, який дефект, який документ. Текст дефекту береться з `FACTS.json`.

Потік даних:

```
джерело (наш PDF, потім паспорт, пункт норми, звіт аварії)
        ↓
inbox/raw/          файл як отримали, без правок
        ↓
inbox/records/      одна картка = одне твердження, статус unverified
        ↓
перевірка людини або окремого звіряльника, який бачить цитату і сторінку
        ↓
FACTS.json          тільки cited
        ↓
SITE.json           збірка майданчика з фактів
        ↓
Blender             тільки деталі з кіта
        ↓
кадр + чеклист      pass / fail
```

Збирач 3D не читає `inbox/records/` і не читає сирий PDF.

## 5. Контракт картки

Файл: `inbox/records/<record_id>.json`
Ідентифікатор: `rec_` + 8 hex, унікальний. Повтор того самого твердження з того самого джерела не створює другу картку. Повтор фіксується в `seen_in` першої.

```json
{
  "id": "rec_a1b2c3d4",
  "subject": "МСВУ 220.13.В12",
  "kind": "dimension",
  "claim": {
    "name": "diameter",
    "value": 22.0,
    "unit": "m",
    "qualifier": "зовнішній діаметр корпусу"
  },
  "source": {
    "origin": "local",
    "path": "Технологія 06.06.24.pdf",
    "page": 8,
    "quote": "точний рядок OCR",
    "bbox": [0, 0, 0, 0],
    "retrieved_at": "2026-09-23"
  },
  "status": "unverified",
  "conflict_with": [],
  "notes": ""
}
```

`kind` лише з цього списку:

| kind | Що кладе в claim |
|---|---|
| `dimension` | `name`, `value`, `unit`, `qualifier` |
| `node` | `node_type` зі словника розділу 6, `present`: true/false |
| `count` | `name`, `value` (ціле), `unit`: `pcs` |
| `power` | `name`, `value`, `unit`: `kW` |
| `capacity` | `name`, `value`, `unit`: `t/h` або `m3` |
| `standard_clause` | `standard_id`, `clause`, `statement` |
| `defect` | `case_id`, `year`, `mechanism`, `document_title` |
| `image` | `path`, `shows` — без чисел, якщо числа не написані на кадрі |
| `scale` | `sheet`, `sheet_unit`, `world_unit`, `factor` |
| `gap` | `field`, `why_needed` — дірка, не факт |

`status`: `unverified` | `cited` | `rejected`.
`origin`: `local` | `web`.
`unit` для довжини на листі, доки немає картки `scale`: `sheet_mm`, і `value` лишається як на кресленні. У метри переводить лише наявність `scale` зі статусом `cited`.

`bbox` — прямокутник цитати на рендері сторінки в пікселях `[x0, y0, x1, y1]`. Якщо OCR не дав рамку, поле `null`, картка все одно пишеться.

Конфлікт: два `unverified` з різними `value` на той самий `subject` + `claim.name` не зливаються. Обидва лишаються, у кожного в `conflict_with` стоїть id іншого. У `FACTS.json` з пари потрапляє нуль, доки людина не поставить одному `cited`, іншому `rejected`.

## 7. SLICE-1. Що зробити

Мета зрізу: після запуску однієї команди в `inbox/` лежать сирі рендери, картки на все, що вдалося прочитати, і один звіт дірок. Жодної нової геометрії в Blender.

### 7.1 Папки

Створити тільки це:

```
inbox/
  raw/
    pdf_pages/          PNG кожної з 12 сторінок
    ocr/                текст і TSV з рамками слів
  records/              картки JSON
  reports/
    gaps.md             людський список дірок
    gaps.json           те саме машиною
    parse_log.json      сторінка, кількість слів, помилки
```

Сирі файли не редагувати після запису. Повторний прогін перезаписує рендер лише якщо змінилася контрольне хеш-сума PDF. Інакше пропускає.

### 7.2 Кроки парсера

Один скрипт, одна команда:

```
python inbox/parse_local.py
```

Робоча тека скрипта: корінь `d:\autocad project`. Залежності ставити в окреме venv `inbox/.venv`, не в глобальний Python.

Порядок:

1. Відкрити `Технологія 06.06.24.pdf` через PyMuPDF.
2. Переконатися, що сторінок 12. Інша кількість — зупинка з кодом 2, картки не писати.
3. На кожну сторінку зберегти PNG у `inbox/raw/pdf_pages/page_XX.png`. Масштаб рендера: 300 dpi. Менше — OCR розмірів на таблицях розвалиться.
4. OCR кожної сторінки рушієм з мовами `ukr+rus+eng`. Зберегти звичайний текст і TSV зі словом і bbox.
5. Окремим проходом прочитати `Plant3D_Equipment_Catalog.json` і покласти кожне числове поле карткою. `source.path` = цей файл, `source.page` = null, `notes` = «каталог, зібраний раніше зі специфікації PDF».
6. Зіставити рядки OCR з відомими тегами зі словника (МСВУ 220.13.В12, Н-100, У13-ТЦС-320, У13-ТЭА, У13-ТЭР, У13-УН175). Збіг тега і числа на тій самій сторінці дає картку `dimension` / `power` / `capacity` / `count`. Число без тега на сторінці не прив’язувати вгадуванням: писати `gap` або лишати в `parse_log` як `unbound_number`.
7. Пройти таблицю словника. Для кожного поля з колонки «чого бракує», якщо немає картки, дописати `gap`.
8. Записати `gaps.md` і `gaps.json`.
9. Існуючі картки не дублювати (ключ: `subject` + `kind` + `claim.name` + `source.path` + `source.page` + нормалізоване `value`).

Парсер не ходить у мережу. Мережа — це SLICE-2.

### 7.3 OCR, якого зараз немає

Перевірка 2026-09-23: команди `tesseract` у PATH немає. PyMuPDF і ezdxf є.

Агент SLICE-1 ставить OCR локально і фіксує у `parse_log.json` назву і версію рушія. Прийнятний варіант: Tesseract 5 з мовними пакетами `ukr`, `rus`, `eng`. Якщо ставлення Tesseract на цю Windows не вдалося, зупинка з зрозумілим рядком у логу. Не підміняти OCR «прочитав очима і вписав числа в картки» без bbox.

Готові нарізки `Технологія 06.06.24_Images\` (тисячі BMP) не є входом SLICE-1. Повний рендер сторінки тримає таблицю разом. Нарізки можна згадати в логу як невикористане джерело.

### 7.4 Критерії здачі SLICE-1

Усі пункти обов’язкові.

1. `python inbox/parse_local.py` завершується кодом 0 на незміненому PDF.
2. У `inbox/raw/pdf_pages/` рівно 12 PNG.
3. Є картки на кожне число з розділу 6, колонка «що вже є числом», статус `unverified`, джерело каталогу вказане.
4. Є хоча б один OCR-прохід: `parse_log.json` містить версію рушія і кількість розпізнаних слів на кожну сторінку. Нуль слів на всіх сторінках — зріз не зданий, це поломка OCR, а не «текст відсутній».
5. `gaps.json` містить дірки з колонки «чого бракує» для силоса, норії, аерації. Поля, які OCR закрив карткою, у дірках відсутні.
6. Жодна картка не має статусу `cited`.
7. Файлів `FACTS.json` і `SITE.json` скрипт не створює.
8. У Blender нічого нового не з’явилося. Доказ фази 0 не перезаписаний.
9. Повторний запуск не подвоює кількість карток.
10. У звіті людиною читається список: що знайшли, що лишилось діркою, які числа не вдалося прив’язати до тега.

### 7.5 Що вважати провалом спроби, а не приводом вигадувати

- OCR ставить сміття в `value`. Тоді картка не пишеться, рядок іде в `parse_log.json` → `rejected_tokens` з причиною `not_a_number` або `no_subject`.
- Тег на сторінці є, числа поруч немає. Картка `node` з `present: true` і окремий `gap` на розмір.
- Сторінка не читається взагалі. Лог, код виходу 1, часткові картки з каталогу лишаються, бо вони не залежать від OCR.

## 8. SLICE-2 і далі. Карта, не завдання цього заходу

Робити після здачі SLICE-1. Інший агент не починає це «заодно».

**SLICE-2. Зовнішній обхід дірок.** Вхід: `gaps.json`. На кожну дірку агент шукає паспорт виробника цього тега, каталожний лист або пункт норми. Кожна знахідка: файл у `inbox/raw/web/<record_id>/`, картка зі `origin: web`, URL, дата, цитата. Статус знову `unverified`. Немає документа — дірка лишається, агент пише `searched` у звіті: де шукав, що відкрив, чому відхилив. Тиша замість звіту не приймається.

Прийнятні джерела: сайт виробника, PDF паспорта, текст норми з номером пункту, звіт OSHA / судове або технічне розслідування з URL. Не прийнятні: маркетплейс 3D-моделей, ролик «3D-світ», стаття без розміру і без посилання на первинку, фото з `ELEVATOR_REFERENCES`.

**SLICE-3. Затвердження.** Людина або окремий прохід, який показує цитату поруч із числом, ставить `cited` або `rejected`. З `cited` збирається `FACTS.json`. Конфлікти без рішення в FACTS не входять.

**SLICE-4. Зовнішній кіт одного силоса.** Тільки поля силоса, які в FACTS є. Blender, масштаб 1 м = 1 м, стіни з товщиною, дах знімається. Поле без факту в моделі відсутнє і назване в кадрі підписом «немає факту», а не заповнене правдоподібною геометрією.

**SLICE-5. Збирач.** Два різні `SITE.json` дають два майданчики без руки.

**SLICE-6. Контроль кадру.** Навмисно зламана сцена (об’єкт під землею або діаметр не той) не проходить. Чиста проходить.

**SLICE-7. Мінімум нутра і режисер.** Аерація, один дах-вентилятор, люк або драбина — лише якщо вони `cited`. Обліт: зовні → люк → всередину → розріз.

**SLICE-8. Перший ролик.** Силос + норія + один дефект з `kind: defect` і статусом `cited`. 40–70 секунд. Кандидати дефекту, які вже названі і ще не розібрані документами: Transcona 1913 (крен 27° через несучу здатність ґрунту), Fargo 1955 (деталей у сховищі немає), DeBruce (звіт OSHA по пиловому вибуху, це послідовність подій, не один розріз). Вибір дефекту цим PRD не зроблено. До SLICE-8 його робити не потрібно.

## 10. Порядок для агента, який закриває SLICE-1

1. Прочитати цей файл цілком і розділ 3. Не читати історію старих скриптів `add_7th_silo.py`, `DRAW_RED_FINAL.py` як зразок.
2. Створити дерево `inbox/` з розділу 7.1.
3. Поставити Tesseract з ukr, rus, eng. Перевірити `tesseract --version` і `tesseract --list-langs`.
4. Написати `inbox/parse_local.py` за розділом 7.2. Без мережі, без Blender, без COM.
5. Прогнати двічі. Другий прогін не додає карток.
6. Залишити `inbox/reports/gaps.md` таким, щоб людина за п’ять хвилин бачила дірки.
7. Зупинитися. Не переходити до SLICE-2, навіть якщо дірки очевидні і пошук «сам проситься».

Звіт здачі, коротко, у кінці роботи агента:

- шлях до `gaps.md`
- кількість карток і скільки з них з каталогу, скільки з OCR
- версія Tesseract і мови
- що не вдалося прочитати
- підтвердження, що `FACTS.json` не створено і Blender не чіпали
